Fixing My Own Blog, Five Years Later

A follow-up to my first two posts, with what I got wrong back then.

In 2021 I wrote two posts about setting up this blog with Hugo and GitHub Pages. I said I was "all set". Five years later I came back to it, and I wasn't.

What was broken

  • The theme was never committed. I'd added it as a git submodule, but the .gitmodules file was malformed and the themes/dream folder was empty in the repo. Hugo had nothing to build with.
  • The deploy workflow was in the wrong folder. GitHub only runs workflows from .github/workflows/. Mine was in workflows/, so it never ran once.
  • The CNAME file was wrong. It contained https://blog.ftchen.site. A CNAME file should hold only the domain name, and it needs to be in the published output.
  • The domain had expired. GitHub Pages still had the custom domain saved, so ftchen93.github.io redirected to a domain that no longer existed.

What I did instead

I dropped Hugo and rebuilt the site as plain HTML and CSS. There's no build step and no theme to keep updated, so GitHub Pages serves the files exactly as they are in the repo. For a personal site with a handful of posts, that's a much better trade.

Then I removed the expired custom domain in Settings → Pages so the site loads at its GitHub address again.

Lessons

  1. "It works on my machine" applies to blogs too. Check the live URL, not localhost.
  2. Fewer moving parts means fewer things to break while you're not looking.
  3. Put domain renewals in your calendar.
