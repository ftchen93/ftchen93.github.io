Automating CRM End-to-End Tests with Selenium and Pytest

How we automated about half of our manual end-to-end cases, and what made the tests stable.

A big part of my current job is end-to-end automation for a Microsoft Dynamics 365 CRM, covering case management and customer management. These are long, form-heavy flows that used to be tested entirely by hand.

We started with a backlog of a few hundred manual end-to-end cases. So far about half of them are automated and validated, as part of a team suite of well over a thousand tests. Here's what made the difference.

1. Seed and clean data through the Web API

Clicking through the UI to create a customer before every test is slow and fragile. Dynamics exposes the Dataverse Web API, so each test creates exactly the records it needs through the API, runs the UI steps it actually cares about, and deletes everything afterwards.

2. Wait for the app, not for the clock

Model-driven apps load forms in stages, so time.sleep() is either too short or wastes time. Explicit waits on the element or state you need next fixed most of our timing failures.

3. Pick locators that survive a release

Generated IDs change. Labels, ARIA attributes and the field's logical name are much more stable. TODO: one or two locator patterns that worked well for you.

4. Run in CI with honest reporting

The suite runs in GitLab CI, with automatic retries for genuinely flaky infrastructure, and results flow into Jira Xray so the whole team can see coverage per test case. Retries are tracked, so a test that only passes on the second try still gets looked at.

5. Validate before you count it

We only mark a manual case as automated after someone has checked that the script really covers the same steps and assertions. It's slower, but "automated" then actually means something.
