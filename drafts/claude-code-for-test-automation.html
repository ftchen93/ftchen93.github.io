Using Claude Code to Write Test Automation

It made me faster. It also needed reviewing more than I expected.

For a while now I've been using Claude Code, an AI coding assistant that runs in the terminal, to draft test scripts at work. This post is about how I use it, what it's good at, and the guardrails we put around it.

How I use it

  1. I give it the manual test case, the existing page objects and fixtures, and one or two tests that follow our conventions.
  2. It drafts the new test in the same style.
  3. I run it, read every line, and fix what's wrong.
  4. A teammate reviews it like any other merge request.

Where it helps

  • Boilerplate. Fixtures, page objects and API payloads that follow an existing pattern.
  • Coverage from a spec. Given an OpenAPI spec, it's quick at listing every operation and drafting a basic test for each. I used this approach on an API suite covering more than a hundred operations across a few dozen service specs.
  • Reading unfamiliar code before I change it.

Where it needs watching

  • Assertions that look right but check the wrong thing, or check too little.
  • Inventing a helper that doesn't exist in our codebase.
  • Tests that pass for the wrong reason. Always make a new test fail once on purpose.
